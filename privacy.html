PRE-RELEASE / PRIVACY NOTICE

Your privacy

This is a pre-release policy draft. Public collection remains disabled until the owner reviews the deployment, retention and user-deletion controls. This page will be updated with an effective date before public launch.

Data and purpose

If you opt in to MYRAA's public device registration, the service uses a random installation ID, operating system, app version, optional release channel, last-seen time, device public verification key and approximate country to handle installation licences, updates, alerts and basic operations. A device is not a uniquely identified person. Server-derived country is coarse. Email and profile details are not needed for anonymous installation tracking.

Apex waitlist (optional)

If you choose to join the MYRAA Apex waitlist on this website, we store only your email address and the time you gave consent. Joining requires ticking an explicit consent box. The single purpose is to tell you when MYRAA Apex becomes available; the email is not used for advertising, is not sold, and is not linked to any device registration. No IP address, user agent or tracking identifier is stored with it. You can ask for your waitlist email to be deleted at any time; a verified contact for these requests will be published before the waitlist opens publicly. The waitlist is not required to download or use MYRAA.

Optional analytics

Usage and crash reporting require distinct opt-in choices. If PostHog EU is activated later, session replay and automatic event capture will remain disabled. The application must not upload chat transcripts, voice recordings, contacts, screen images, typed input, documents or file contents to MYRAA's owner dashboard.

Third-party infrastructure

Cloudflare may handle connection metadata, including network addresses, under its own service terms. The Worker does not intentionally store full IP addresses in the application database; abuse prevention uses secret-salted hashes. Installer files are hosted on the official GitHub release repository once it exists. Some AI functions may use third-party model providers separately from this metadata dashboard.

Consent and choices

Required registration/licence/update metadata is explained during onboarding; any optional usage/crash analytics default off. You may decline optional reporting or later withdraw permission where supported. If reporting is not enabled, the desktop application is designed to keep local tasks available without the online control plane.

Access, export and deletion

For registered devices, the service implements authenticated POST /v1/me/export and POST /v1/me/delete requests signed by the device. Deletion removes that device's registration and linked licences. The corresponding in-app controls are still in development, so public release is blocked until they are tested. Do not confuse deleting an install record with deleting third-party model-provider data.

Retention

Active installation records remain until device deletion or revocation. Automated time-based removal of dormant records must be implemented and verified before public launch. Optional crash and usage data will have separately documented retention limits if enabled. Owner actions may be logged to detect abuse.

India privacy compliance

This product aims to meet applicable India Digital Personal Data Protection requirements. Final notices, grievance contact and any required age/guardian consent workflow must be reviewed before launch. This draft does not claim completed legal certification.

Contact

A verified product support/grievance contact is not yet configured. Public launch is on hold until that is available.
